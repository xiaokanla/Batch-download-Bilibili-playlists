# 用户指南

## 1. 第一次使用

1. 启动 `python web_app.py`。
2. 打开 `http://127.0.0.1:8765`。
3. 点击“扫码登录”，使用 B 站 App 扫码。
4. 在“路径设置”中配置：
   - 程序数据目录：保存历史记录、缓存和配置。改动后重启生效。
   - 默认下载目录：视频下载到哪里。
   - FFmpeg / FFprobe：高清音视频合并和抽帧需要。
   - Aria2：可选下载器；不稳定时程序会自动回退内置下载器。
   - Eagle 导出/缓存目录：封面、套图、弹幕缓存等中间文件。
   - 错误日志文件：下载失败详情保存位置。
5. 点击“环境诊断”的“运行”，先确认 FFmpeg、FFprobe、下载目录、Eagle API 和写入权限是否正常。

首次启动时，程序会在“程序数据目录”中创建 `bili_downloader.db`。如果目录里已有旧版
JSON 文件，程序会自动迁移；旧 JSON 不会被删除，后续仍会同步写入兼容镜像。

## 2. 同步收藏夹

1. 在左侧“数据源”选择收藏夹。
2. 点击“同步收藏夹”。
3. 中间列表会显示视频封面、标题、BV、时长和下载状态。
4. 可以用搜索、时长、月份柱状图、仅看未下载来筛选。

## 3. 下载视频

1. 勾选要下载的视频。
2. 确认右侧“下载”区域的保存目录、清晰度和限速。
3. 点击“启动下载”。
4. 下载完成后程序会写入下载记录，之后同一 BV 会显示为已下载。
5. 在列表中右键视频，可以直接打开对应的 B 站视频网页，也可以复制 BV 号。

## 4. 下载指定账号的投稿

这个功能位于顶部的“账号投稿”页签，与收藏夹下载分开。它适合下载某个账号的公开投稿，例如选择“原神”官方账号后，再用顶部搜索栏筛选“角色 PV”。

1. 点击顶部“账号投稿”。
2. 输入账号名称、UID，或该账号的空间主页链接。
3. 点击“查找账号”，在候选账号中确认正确的账号。
4. 点击“获取投稿列表”，等待列表加载完成。
5. 在顶部搜索栏输入 `角色 PV`、标题片段或 BV 号筛选列表。
6. 在中间列表勾选视频后，按普通下载流程点击“启动下载”。

账号检索只请求一次；投稿列表按页低频串行获取。公开视频较多时需要耐心等待，不要在任务进行中重复点击。如果出现风控提示，先停止操作并等待一段时间后再试。

## 5. 标签关系图分析

标签关系图用于查看当前已加载列表中，某一时间范围内视频的大致主题类型和标签之间的关联。收藏夹、账号投稿和手动列表都可以使用。

1. 先加载收藏夹、账号投稿或手动视频列表。
2. 在右侧“标签分析”选择近 3 个月、近 6 个月、近 1 年，或指定月份。
3. 需要只分析已经下载的视频时，勾选“仅已下载”。
4. 点击“生成关系图”。
5. 第一次生成时，程序会逐个低频读取尚未缓存的视频标签；完成后的标签会保存在本机，下一次相同或相近范围分析会快很多。
6. 节点越大表示标签出现越频繁，节点之间的线表示它们出现在同一视频中，线越粗表示共现次数越多。点击任意节点，主列表会立即只显示带该标签的视频；点击右上角 `×` 可清除标签筛选。

关系图不会在同步收藏夹或获取投稿时自动读取标签。标签请求始终为串行低频；遇到 `-412`、`-352`、`403`、`412` 或 `429` 限制响应会立即停止，已缓存的结果仍然可以使用。

## 6. 换设备不重复下载

旧设备：

1. 点击“导出记录”。
2. 选择一个方便传输的目录，保存生成的 `bili_history_bundle.json`。

新设备：

1. 点击“导入记录”。
2. 选择 `bili_history_bundle.json`，或者直接选择旧设备数据目录中的 `download_records.json`。
3. 导入成功后再同步收藏夹，已下载过的视频会被标记出来。

迁移包只保存 BV 号、标题、下载时间、原设备路径和 Eagle 信息，不包含视频文件本身。原设备的绝对路径在新电脑上通常不能直接使用，但 BV 号仍可用于去重和重新定位。导入后如果总记录数没有变化，请确认选择的是 JSON 文件，而不是空的下载目录；也可以直接选择旧设备的 `userdata` 文件夹，程序会自动寻找记录文件。

如果希望整体迁移，除了历史记录包，也可以复制旧设备的数据目录。目录中的
`bili_downloader.db` 是新版本的主数据库，`app_settings.json` 保存数据目录位置。
复制到新设备后，在“路径设置”中重新确认下载目录、FFmpeg、FFprobe、Aria2 和 Eagle
库路径；视频文件本身不会因为迁移数据库而自动复制。

## 7. Eagle 导入视频

1. 打开 Eagle。
2. 在 BiliDownloader 右侧 Eagle 区域选择 `.library` 目录。
3. 选择要导入的 Eagle 文件夹。
4. 选择速度模式：
   - 快速：更少帧，速度优先。
   - 平衡：推荐。
   - 高质量：更多候选帧，会更慢。
5. 点击“导入已下载视频到 Eagle”。
6. 如果勾选“导入后删除源视频”，成功导入后会删除下载目录中的原视频。
7. 右侧任务区会显示进度、成功数、失败数和最近错误。失败项目可以根据错误提示处理后重新执行。

## 8. 修复 Eagle 文件夹封面

用于处理已经在 Eagle 库里的本地视频。

1. 选择 Eagle 库和目标文件夹。
2. 默认会跳过已经有自定义封面的条目。
3. 如果要全部重做，勾选“强制刷新已生成封面”。
4. 点击“修复选中文件夹封面”。

匹配逻辑：

- 优先用 Eagle 条目中的 BV、URL、标签或备注。
- 再用历史下载记录、收藏夹缓存、旧 manifest 里的标题匹配。
- 如果能匹配到 BV，会使用 B 站封面和本地/缓存弹幕峰值。
- 如果匹配不到 BV，不再请求封面或弹幕，直接从本地视频抽帧生成套图。

## 9. 常见问题

### 下载后没有声音

通常是音视频分离流没有合并成功。请确认 FFmpeg 路径有效。

### 部分电脑 aria2 下载失败

程序会自动回退到 yt-dlp 内置下载器。也可以在“路径设置”里清空 Aria2 路径。

### Eagle 缩略图没马上变化

Eagle 可能缓存缩略图。切换文件夹、刷新 Eagle 或重启 Eagle 后再看。

### 不知道哪里配置错了

先运行“环境诊断”。如果出现“处理”或“建议”，按提示检查路径、Eagle 是否打开、`.library` 目录是否选对。诊断只检查本机环境，不会批量请求 B 站。

### B 站搜索返回 412

这是请求被限制或响应异常的表现。程序会优先使用本地缓存，避免频繁请求。不要短时间重复大批量搜索、账号检索或投稿同步。

### 新设备首次同步触发风控

新设备没有收藏夹缓存时，程序会自动使用低频串行同步：首次请求前等待一小段时间，分页请求之间保持更长间隔，并在检测到 `-412`、`-352` 等风控响应时立即停止。首次同步可能比旧版本慢，这是为了降低登录后短时间内的请求突发。遇到风控后不要连续点击同步，等待一段时间后再重试。

### 导出的记录导入后显示为空

请优先使用“导出记录”生成的 `bili_history_bundle.json`。如果使用“打开记录位置”，要复制其中的 `download_records.json`，不要只复制其他缓存文件。新版本同时兼容完整记录包、原生 `download_records.json`、旧版 `history.json`、`bili_history.json` 和旧版 BV 列表。

### 标签关系图生成很慢或中途停止

首次生成需要补齐本地没有缓存过的视频标签，因此会刻意按低频串行方式运行。不要为了加速同时多开程序或连续点击生成。若遇到风控，程序会停止；等一段时间后再次生成，已成功读取的标签会从本地缓存直接使用。

### SQLite 数据库和 JSON 有什么关系

新版本优先从 `bili_downloader.db` 读取数据，JSON 是为兼容旧版本和独立脚本保留的镜像。
正常使用时请优先使用程序内的“导出记录”功能，不要手动同时修改数据库和 JSON。
如果直接用旧版程序或外部脚本改了 JSON，新版程序不会自动检测外部 JSON 的变化；可先导入记录，
或删除对应数据库后重新启动，让旧 JSON 再次迁移。
